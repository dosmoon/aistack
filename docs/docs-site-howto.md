# Docs Site — Update Howto

How to update the published docs site (`dosmoon.com/aistack`) without
re-discovering the fiddly bits each time.

## Where things live

| What | Path | Edit? |
|---|---|---|
| English narrative pages | `docs/public/*.md`, `docs/public/{api,reference,research}/index.md` | ✅ |
| Chinese narrative pages | `docs/public/zh-cn/*.md`, `docs/public/zh-cn/{api,research}/index.md` | ✅ |
| Auto-generated API reference | `docs/public/api/*.md` (asr/tts/llm/...) | ❌ regenerated each build |
| Auto-generated config reference | `docs/public/reference/configuration.md` | ❌ regenerated each build |
| Sidebar order + top-level labels | `site/astro.config.mjs` | ✅ |
| Generators (source → markdown) | `scripts/gen_api_reference.py`, `scripts/gen_config_reference.py` | ✅ if you need to change frontmatter or section labels in the generated output |

`site/src/content/docs/` is **build output** — gitignored, wiped and
rewritten by `site/scripts/sync-docs.mjs` on every build. Never edit it.

## Common tasks

### Edit existing prose

Edit the file under `docs/public/...` (and the matching `zh-cn/`
counterpart for narrative pages). Commit, push to `main`. CI deploys.

### Add a new page inside an existing section (api/, reference/, research/)

Drop the `.md` into the folder. The folder is autogenerated in the
sidebar — frontmatter `sidebar.order` controls position **inside** the
folder. No code changes needed.

### Add a new top-level page

1. Create the `.md` in `docs/public/` (and `docs/public/zh-cn/` if it's
   narrative — see bilingual policy below).
2. Add an entry to the `sidebar` array in `site/astro.config.mjs`. The
   array is the source of truth for top-level order; frontmatter
   `sidebar.order` does **not** work reliably when files and folder
   groups are mixed at the top level (Starlight 0.39 autogenerate
   didn't honor it — that's why we went explicit).

### Reorder top-level entries

Edit `site/astro.config.mjs` `sidebar` array. Order = array order.

### Change a section's auto-generated title or sidebar metadata

For `reference/configuration.md`: edit `FRONTMATTER` in
`scripts/gen_config_reference.py`.
For `api/*.md`: edit `scripts/gen_api_reference.py`.

## Bilingual policy

- Narrative + research pages: bilingual. EN under `docs/public/`,
  matching ZH under `docs/public/zh-cn/`.
- Auto-generated reference (API + config): English-only. Don't add a
  `zh-cn/api/*.md` or `zh-cn/reference/configuration.md` — there's no
  pipeline and the source is in English (docstrings, field names).
- Don't unilaterally rewrite Chinese technical titles. Propose options.

## Local preview

```bash
cd site
pnpm install      # first time only
pnpm dev
```

`pnpm dev` runs `sync-docs.mjs` (which runs the Python generators) then
starts Astro dev server. Generators need a working Python 3.10+ on PATH;
they're pure AST, no `pip install` required. Set
`AISTACK_SKIP_API_GEN=1` to bypass generators (faster iteration on
narrative-only changes; auto-generated pages will be stale or missing).

## Deploy

Push to `main`. `.github/workflows/deploy-site.yml` triggers on changes
under `docs/public/**`, `site/**`, or the workflow file itself. Builds
on Ubuntu, deploys to GitHub Pages. Check status:

```bash
gh run list --limit 3 --workflow=deploy-site.yml
gh run view <run-id> --log-failed
```

## Things that have bitten us

- **editLink removed**: Starlight's `editLink.baseUrl` produces 404s
  because Starlight appends the *synced* path (`site/src/content/docs/...`)
  not the *source* path (`docs/public/...`). Don't add it back without
  fixing the path mismatch (would need per-file `editUrl` injection
  during sync).
- **Two "Configuration" entries**: there's a top-level narrative
  (`docs/public/configuration.md`) and an auto-generated reference
  (`docs/public/reference/configuration.md`). Sidebar labels are
  `Configuration` and `Configuration Reference` — keep them
  disambiguated.
- **Starlight 0.39 sidebar API**: when using `autogenerate` for a
  folder group, wrap it in `items: [{ autogenerate: { directory: '...' } }]`
  — combining `label` with `autogenerate` directly is a build error.
