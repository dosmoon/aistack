# P0 verification — unified GPU lock + cancel propagation

> Live verification of the P0 fix landed in commits `40168e6` (lock + cancel)
> and `ed03278` (smoke tests). Pytest covers the lock primitive and the
> route-level 503 behavior with mocked upstreams; this document records
> the **on-host run with real Ollama and real Qwen3-TTS** so we have a
> baseline to compare against in future regressions.

## Scenarios

### S1 — single non-streaming LLM call (smoke)

```
POST /v1/chat/completions  {"model":"qwen3:4b", stream:false}
→ HTTP 200, response body well-formed (chatcmpl-* shape)
```

**Result:** ✅ Ollama proxy unbroken by the lock refactor; `keep_alive`
default still injected.

### S2 — concurrent LLM × LLM, cross-capability mutex

Two requests launched 0.3 s apart, both targeting `/v1/chat/completions`:

| Req | Outcome |
|---|---|
| req1 | HTTP 200 after **25.234 s** (real Ollama generation) |
| req2 | HTTP 503 after **3.6 ms**, `Retry-After: 5`, body `{"detail":"aistack GPU slot is busy (held by llm); rejected llm. Retry after a few seconds."}` |

**Result:** ✅ Cross-capability mutex works in production; rejection is
fast (no upstream call), `Retry-After` header present, holder name
correctly identified.

### S3 — streaming LLM with mid-flight client disconnect

```
curl -sN --max-time 3  POST /v1/chat/completions  {stream:true, ...}
→ curl exits at T=3.146s with partial SSE
follow-up (non-streaming) fired immediately at T=3.146s
→ HTTP 200 in 5.516 s (own generation time)
```

**Result:** ✅ Slot released on TCP close. The follow-up did **not**
hit 503 and did **not** wait for the original Ollama request to finish
naturally — proving the StreamingResponse generator's `finally` ran
when uvicorn closed the response.

### S4 — kept-warm sequential calls

After several disconnects and follow-ups, six consecutive
`/v1/chat/completions` requests over a few minutes all returned 200
with no 5xx and no apparent leak. Server `/health` and `/v1/models`
remained responsive throughout.

**Result:** ✅ No deadlock, no orphan locks, no zombie httpx clients.

## Caveats / non-results

- **No "client disconnected; aborting upstream LLM stream" log line was
  emitted** in any S3 attempt. This means `request.is_disconnected()`
  did not flip to `True` between yields fast enough to hit our explicit
  `break` path. Functionally fine: the StreamingResponse generator's
  `finally` clause still runs when uvicorn closes the body iterator on
  TCP close, releasing the slot and `aclose()`-ing the upstream. The
  `is_disconnected()` polling is a latency optimization, not a
  correctness requirement.

- **ASR was not exercised on real audio** in this run because no test
  fixture audio was on hand. ASR's lock path is identical to
  pre-refactor (`busy_or_503` context manager) and is covered by
  `tests/test_endpoints.py::test_llm_returns_503_when_slot_busy` (ASR
  side of the symmetric mutex check). The `cancel_token` wiring on the
  ASR handler is logically correct but not yet observed end-to-end on a
  long real transcription. Should be revisited next time we have
  reproducible long-form audio.

- **TTS was not exercised end-to-end with real audio output.** The
  Qwen3-TTS Docker container was up and `/v1/models` saw it, but a real
  `/v1/audio/speech` call was not part of this verification. Pytest
  covers the route's 503 path with a mocked upstream
  (`tests/test_endpoints.py::test_tts_returns_503_when_slot_busy`).

- **Cross-process VRAM coexistence stress test deferred.** The lock
  prevents *concurrent inference* across capabilities, but the Qwen3-TTS
  container holds ~6.4 GB resident at startup regardless of activity
  (`gpu_memory_utilization=0.80`). Tightening that value is a separate
  P2 follow-up; not part of P0.

## Conclusion

P0 ships green on real upstreams. The two architectural promises that
were missing before commit `40168e6` are now observable:

1. *At most one capability holds the GPU slot at a time.* Verified by
   S2 with a real 25 s LLM generation followed by an instant 503.
2. *Client disconnect releases the slot promptly.* Verified by S3 with
   a follow-up succeeding in real generation time, not blocked on the
   abandoned upstream.

Recommended next checks (out of P0 scope):

- Real ASR cancel observation on a long audio sample (≥1 min),
  watching for backend cancel-token honoured logs.
- Real TTS `/v1/audio/speech` end-to-end while ASR is mid-flight, to
  confirm the lock holds during the proxied container call.
- Re-run S1–S4 after lowering Qwen3-TTS `gpu_memory_utilization` to
  ~0.50 to confirm headroom.
